# RL 실험 기록 (암보이, 1대)

무엇을, 왜 했고, 결과가 어땠고, 다음에 무엇을 정해야 하는지를 한곳에 모은다. 설계 결정의 자세한 이유는 `docs/rl_mdp_design.md`에 있다.
실험을 하나 시작하거나 끝낼 때마다 이 문서의 표를 먼저 고친다.

## 이름표 한눈에 (사용자와 대화할 때 이름표에는 항상 짧은 설명을 붙인다)

| 이름표 | 무엇 | 예 |
|---|---|---|
| A1~A5 | A(탐색 영역 점수)의 정의 | A1 5분 창(기존) · A3 10초마다 실시간 영역 · A4t 실시간 영역, 롤 15° 이하에서 본 칸만 탐색 완료 |
| D1~D3 | 탐지 POD의 흔들림 계수 | D1 5°/s까지 1 뒤 직선 감소(기존) · D2 exp(−선회율/ω₀), ω₀ 15 · D3 롤 5°(1.5°/s)까지 1, 그 위로 exp(−(선회율 − 1.5)/3) |
| B0~B2 | 보상의 추가 항 | B1 직진 보상 c × (1 − \|행동\|) |
| E0~E2 | 실험(채점만 한 것 포함) | E0 amboy_v1, E1·E2 기존 비행 재채점 |
| T1 | 직진 보상 시험 (A1) | amboy_v1 → A1 + B1 0.05, 100만 스텝 |
| R1, R2 … | 실시간 A로 하는 학습 시험 | R1: T1 → A4t(15°) + D2(15) + B1 0.05 + 다양 분포 (40만 스텝에서 멈춤) · R2: R1 40만 → A4t(10°) + D2(15) + 총점 A + 1.5 POS + B1(정책 행동) + 마스크 비용 + 나가는 particle 5% 이하 분포 · R3: R2 50만 → A4t(5°) + D3, 나머지 R2와 같음 · R4: R3 → D4(손해 없는 구간 없음) + A 영역 σ 75 m |

## 지금 코드의 기본값

| 항목 | 기본값 | 바꾸는 곳 |
|---|---|---|
| A 정의 | **A1** (5분 창, σ 150 m, x 70%) | 설정 `area_def`: `window` = A1, `seen` = A2, `realtime` = A3 |
| 보상 | (ΔA + ΔPOS) × 100, 추가 항 없음 (**B0**) | `train_rl --straight-bonus c` = B1 |
| 모델 | amboy_v1 `best_stage3.zip` (620만 스텝) | `train_rl --init <모델>` |
| SAROPS 기준값 | A1: `rl_eval/sarops_ref_<split>.json`. 다른 A는 `sarops_ref_<split>_<area_def>.json` | `sarops_ref --area-def` |

학습 실행마다 `rl_search/data/rl_real/<tag>/config.json`에 쓴 설정(`area_def`, `straight_bonus`, `init` 등)이 남는다.

## A 정의 버전

| 이름 | 내용 | 상태 (날짜) | 근거 |
|---|---|---|---|
| A1 | 5분 창마다 창 끝 시각의 particle(가중치 없음)을 σ 150 m로 흐려 x 70%를 담는 띠. 25 m 칸이 화면에 들어오면 훑음, 한 번만 셈 | 기본 (11-05) | 처음 정의 |
| A2 | 10초마다 particle 상위 80%가 있는 25 m 칸. particle 누적 POD ≥ 0.5면 봤음(particle을 따라다님) | 선택지로만 (11-11) | POS와 너무 비슷함(사례별 상관 0.89~0.92, 사용자: 이중 보상) |
| A3 | A1과 같되 영역을 10초마다 그 시각의 분포로(남아 있는 particle만) | 선택지, 다음 실험 후보 (11-11) | 사용자: A의 영역도 실시간이어야 함 |
| A4 | A3 + 화면 품질: 1초 표본마다 흔들림 계수(POD와 같은 선회율 계수)를 품질 q로, 칸마다 가장 좋은 q를 기억, 더 좋은 화면으로 다시 훑으면 차이만큼 | 구현 (11-11, 사용자), `area_def = realtime_q` | 흔들며 훑은 몫을 깎는다. amboy_v1 시험 10번 비행: A3 0.530 → A4(D2 ω₀ 15) 0.437 |
| A4t | A3 + 롤 기준: 롤이 기준 이하(화면이 안정)인 1초 표본에서 화면에 들어온 칸만 탐색 완료(1), 그 밖은 세지 않음(나중에 다시 훑으면 셈) | 구현 (11-11, 사용자: 방식 (가), 15°), `area_def = realtime_t`, `area_roll_max` | 고정 패턴 시험(검증 1단계 3개, 3분)에서 20°는 중간 크기 흔들기(±0.6)가 여전히 이득(A +16%), 15°는 흔들어도 직진보다 낫지 않음. 카메라가 500 m 앞을 봐서 진행 방향 ±15°만 흔들려도 화면은 옆으로 ±130 m 쓸린다 |
| A5 | A3 + 띠 좁히기(σ 축소) | R4부터 σ 75(`area_sigma`) | 띠가 카메라 폭(약 190 m)보다 넓어 흔들면 A가 오른다 |
| A6 | 도로 칸 위 particle은 σ 75, 도로 밖 particle은 σ 150으로 흐려 더한 뒤 x 70% | 구현 (11-12, 사용자 결정, 다음 묶음), `area_sigma_off 150`, 기준값 이름 `_o150`, 학습 풀 `rl_pool_multi_o150`(`make_pool --multi --n 600 --area-def realtime --area-sigma 75 --area-sigma-off 150`, 시나리오는 기존 풀에서 가져오고 구역만 다시) | σ 75만 쓰면 사막형 구역이 136조각(작은 조각 20%), 바꾸면 30조각(4%), 도로형은 그대로. 같은 결과를 클래스로 다시 만들어 칸 단위로 같음을 확인, 시나리오당 구역 만들기 약 2배(4 → 7 s) |

## 탐지(흔들림 계수) 버전

| 이름 | 내용 | 상태 |
|---|---|---|
| D1 | 선회율 5°/s까지 1, 20°/s에서 0.2까지 직선 | 기본 (11-06) |
| D2 | exp(−\|선회율\| / ω₀): 조금이라도 돌면 낮아짐. POD와 A4의 화면 품질에 함께 | 구현 (11-11, 사용자), 설정 `blur_tau` = ω₀ (0이면 D1). ω₀ 후보 10 / 15 / 20 °/s (`rescore/blur_factor.png`) |
| D4 | D2 × D3: 처음부터 exp(−ω/τ_low)로 조금씩 줄고, 롤 θ의 선회율 위로는 exp(−(ω − 그 값)/τ)가 더 곱해짐. 손해 없는 구간 없음 | 구현 (11-12, 사용자: τ_low 15, θ 5°, τ 3), 설정 `blur_tau_low` (`--blur-tau-low`). 롤 2° 0.96 · 5° 0.91 · 7° 0.71 · 10° 0.49 · 15° 0.26 · 20° 0.14 · 30° 0.03 (`rescore/d4_proposal.png`) |
| D3 | 롤 θ의 선회율(g·tanθ/v)까지 1, 그 위로 exp(−(\|선회율\| − 그 값)/τ). θ를 A4t의 롤 기준과 같게 두면 "A에 세는 화면 = POD를 다 주는 화면" | 구현 (11-11, 사용자: θ 5°, τ 3), 설정 `blur_tau` = τ, `blur_dead_roll` = θ (`--blur-dead-roll`). 롤 10° 0.60 · 15° 0.36 · 20° 0.21 · 30° 0.06 (D2 ω₀ 15는 0.82 · 0.74 · 0.66 · 0.52) |

비행 시간 평균 계수 (시험 30개): SAROPS D1 0.95 → D2 0.80 / 0.86 / 0.89, amboy_v1 0.94 → 0.71 / 0.79 / 0.83, T1 0.96 → 0.76 / 0.83 / 0.86 (ω₀ 10 / 15 / 20).
SAROPS 기준값 파일 이름은 A 정의와 탐지 버전을 함께 쓴다: `sarops_ref_<split>_<area_def>[_d<ω₀>[z<θ>]][_w<w>].json` (`sarops_ref.ref_key`),
예: R2 `realtime_t10_d15_w1.5`, R3 `realtime_t5_d3z5_w1.5`.

## 보상 버전

| 이름 | 내용 | 상태 |
|---|---|---|
| B0 | (ΔA + ΔPOS) × 100 | 기본 |
| B1 | B0 + c × (1 − \|a\|), a = 적용된 행동(학습에만, 평가 점수에는 없음) | 구현, T1에서 c = 0.05 |
| B2 | B0 − c × (롤 반전 횟수). 롤 반전 = 1초 표본의 롤이 +10° 넘는 쪽에서 −10° 넘는 쪽으로(또는 반대로) 넘어감. 마지막 쪽은 스텝 사이에도 기억 | 구현했지만 쓰지 않음 (11-11, 사용자: 어려울 것 같아 B1만). `train_rl --roll-reversal-cost c`, 기본 0 |

### 바로 고친 것 (11-12, 사용자: 가장자리 처리와 인계 규칙은 지금 당장)

- 진단(`scripts/rl_eval/obs_sensitivity.py`, R5 100만, 유형별 검증 사례 3 사막형): 큰 지도는 영향이 크다(51.2 km 지도의 particle 정보를 지우면 첫
  결정부터 행동이 바뀌고 평균 변화 0.78, POS 0 → 0.05). 지도 가장자리 표현은 코드상 맞다(나간 particle은 가중치 0, 지도 밖 가시도 −1, 칸 번호

### 나중 단계 (사용자 11-12 순서: ① 사례별 세부 분석 → ② 속도 → ③ 고도 → ④ 여러 대 → ⑤ 발견 뒤 로이터링·추적)

- ② 속도 조절(추력): 행동에 속도 추가, 속도별 소모 전력(배터리), 속도별 POD(머무는 시간은 이미 모델에 있음). 기체의 최저·최고 속도와
  속도별 전력(또는 비행 시간)이 필요. 흔들림 계수는 롤이 아닌 선회율의 함수로 둔다(같은 롤이면 느릴수록 더 깎임). 먼저 고정 속도로 효과 확인.
- ③ 고도 조절: 높을수록 화면은 넓고 표적 픽셀은 줄어 POD 감소(해상도 계수는 모델에 있음), 상승 에너지, 고도 제한. ②와 배터리 모델 공유.
- ④ 여러 대: 대수 무작위(1~5대) 학습, 각 기체 관측과 critic 전체 상태 재설계. 몇 대를 띄울지는 대수별 성능 곡선으로.
- ⑤ 발견 뒤: 짐벌로 표적을 계속 보며 표적 둘레를 도는 궤도, 따라가며 돌기, 놓치면 재탐색, 여러 대면 교대, 지상 인력 유도.
  무기로 타격하는 "스트라이크" 설계는 돕지 않기로 함(감시·추적·유도만).
- 3축 짐벌(방위 축): 언젠가 고려(사용자). 지금은 2축에서 비행 경로 안정화를 먼저.

운영 메모 (11-12, 사용자: 용량이 빨리 참): `train_rl --save-every 500000`이면 평가는 `--eval-every`마다 하되 체크포인트와 평가 웹 실행은

## 정할 것

- B2의 크기 c: c = 0.05면 지금 RL처럼 날 때 비행당 약 0.11점(A + POS 단위), SAROPS처럼 날 때 약 0.04점을 잃는다. 0.1이면 0.22와 0.07.
- A4의 σ와 흔들림 기준(선회율 몇 °/s 이상을 세지 않을지).
- PX4 연동 방식(나중): 5초마다 진행 방향 명령을 보내는 실시간 고리(학습과 같음) 또는 몇 분마다 짧은 경로를 다시 올리는 방식.
- 기체 안(Jetson)의 비행 중 belief 갱신(나중, 11-11 논의): 계산량은 문제없다(5초마다 0.1초 안쪽). 시뮬레이터의 belief 갱신과 정책은
  무작위 요소가 없어서, 못 찾고 기체가 모델대로 날면 실시간 고리와 미리 돌린 경로가 같다. 실시간 반영은 현실이 모델과 다를 때를 고친다.
  정할 것: 사진마다 촬영 시각을 붙여 그 시각의 위치·자세로 화면 위치를 계산, 처리 못 한 프레임은 belief를 줄이지 않음("안 봤음"),
  탐지 시 확인 비행으로 전환(정책 밖 규칙)과 오탐 처리, 새 신고 시 particle 다시 예측, 실제 POD(Gazebo + YOLO로 측정, 그 전까지 보수적으로).
