# 단일 UAV PPO 기준안과 조정 기준

2026-10-30 · 추천안 v1. 아래 수치는 실험 출발점이며 아직 채택·구현한 설정이 아니다.
기존 합의가 우선이며, 알고리즘의 시간 할인과 커리큘럼에 대한 보류 결정을 대체하지 않는다.

## 1. 근거와 적용 범위

- 지도 3개(각 2×64×64), 기체 벡터 6개, 연속 행동 1개, 5초 행동 주기.
- 추가 입력 검토: 마지막 표적 이동 방향·속도를 vx,vy로 제공하는 방법을 우선 검토 중이다. 정보 경과 시간까지 추가하면 벡터는 9개가 되지만 아직 미확정이다. 아래 파라미터 수·레이어 표기는 기존 6개 기준이며 입력 확정 시 갱신한다. 미래·과거 지도 및 순환 모델은 후속 비교 후보로 둔다.
- 해상도별 독립 CNN 3개, actor/critic 사이 특징 추출부 공유, 후단 MLP 분리.
- PPO의 공유 특징 추출과 독립 pi/vf MLP는 SB3 공식 구조에 부합한다.
- CNN 폭·깊이와 아래 설정은 프로젝트에 맞춘 제안이며 문헌이 보장하는 최적값은 아니다.
- 현재 설치된 SB3 2.9.2의 PPO/정책 시그니처를 확인했다. 웹 자료는 접근 가능한 공식 문서 v2.3.2와 OpenAI Spinning Up을 확인했다.

참고: [SB3 Custom Policy](https://github.com/DLR-RM/stable-baselines3/blob/v2.3.2/docs/guide/custom_policy.rst),
[SB3 PPO](https://github.com/DLR-RM/stable-baselines3/blob/v2.3.2/docs/modules/ppo.rst),
[OpenAI PPO 설명](https://spinningup.openai.com/en/latest/algorithms/ppo.html).

## 2. 네트워크 기준안 B

각 지도: Conv(2→16, 3×3, stride 2, padding 1) → ReLU →
Conv(16→32, 3×3, stride 2, padding 1) → ReLU →
Conv(32→32, 3×3, stride 2, padding 1) → ReLU →
Flatten(32×8×8) → Linear(2048→128) → ReLU.

- 지도별 출력 128개를 연결한다. 공간 위치를 구분해야 하므로 전역 평균 풀링은 초기안에서 제외한다.
- 기체 벡터: 6→32→32, ReLU.
- 결합: 384+32=416 → 256, ReLU. 여기까지 actor/critic이 공유한다.
- Actor MLP: 256→128→128, Tanh → 평균 1개. SB3의 학습 가능한 상태 독립 log_std를 사용한다.
- Critic MLP: 256→128→128, Tanh → 상태 가치 1개.
- 약 104만 파라미터. Dropout/BatchNorm은 초기안에 추가하지 않는다.
- PPO 기본 Gaussian과 행동 범위 clipping을 사용한다. 초기 log_std=-1을 후보로 두고 행동 포화 비율을 기록한다.
- 기하학적 정보가 부족하면 CNN 깊이를 늘리기 전에 축소된 지도에서 관측 띠와 입자 분포가 실제로 구별되는지 확인한다.

## 3. PPO 기준 설정

| 설정 | 초기 후보 | 이유/주의 |
|---|---:|---|
| 환경 수 | 2 | 다양한 궤적 수집. Mac 자원이 부족하면 1로 시작 |
| n_steps | 환경당 1024 | 총 2048 전이/업데이트. 수집 중 에피소드를 임의 종료하지 않음 |
| batch_size | 64 | 지도 입력의 메모리 부담 제한 |
| n_epochs | 5 | 같은 수집 자료에 과도하게 맞추는 업데이트부터 피함 |
| learning_rate | 1e-4 | 공유 CNN을 포함한 보수적인 초기 학습률 |
| clip_range | 0.2 | PPO 기본 출발점 |
| target_kl | 0.02 | clipping만으로 큰 정책 변화를 막지 못하는 경우 조기 업데이트 중단 |
| gae_lambda | 0.95 | 첫 비교 기준. 장기 학습 실패 시 0.98을 별도 비교 |
| ent_coef | 0.005 | 초기 탐색용 후보. 학습된 std와 실제 행동을 함께 확인 |
| vf_coef | 0.5 | 초기 actor/critic 손실 균형 |
| max_grad_norm | 0.5 | 큰 기울기 제한 |
| normalize_advantage | True | SB3 기본 방식 유지 |
| clip_range_vf | None | 보상 스케일에 의존하는 추가 제한은 우선 제외 |
| optimizer | Adam | SB3 기본 설정 사용 |
| gamma | 첫 파일럿 후보 1.0 | 에너지 종료의 유한 임무와 최종 성과 목적에 맞춤. 최종 할인 방식은 결과 후 결정한다는 기존 보류 유지 |

5초 주기에서 gamma=0.99는 약 5.7분 뒤 보상의 가치를 절반으로 낮춘다.
이를 라이브러리 기본값이라는 이유만으로 적용하지 않는다. gamma 변경은 목적의 시간 선호 변경으로 취급한다.

## 4. 학습 전 통제 조건

- 관측은 확률/비율 float32이며 일반 사진이 아니다. 자동 /255 이미지 정규화를 적용하지 않는다.
- 확률은 초기 질량 기준을 유지한다. 입력 배율이 필요하면 지도별 고정 배율을 학습·평가에 동일하게 적용한다.
- 확률 질량 크기·0의 의미를 바꾸는 지도별 재정규화나 온라인 관측 정규화는 기본안에 추가하지 않는다.
- 정책 학습 전에 고정 경로들로 POS·면적·시간 보상의 원시값과 가중값을 따로 측정한다.
- 보상 단위·고정 스케일과 가중치를 정하기 전에는 네트워크 비교 실험에 들어가지 않는다.
- 시간 보상이 탐색을 압도하는 문제는 더 큰 CNN으로 해결하지 않는다.
- 첫 장치 기준은 CPU. 실제 Mac의 칩·메모리·환경 생성 속도를 확인한 뒤 MPS 및 병렬 실행을 비교한다.
- 지도 관측만으로 2048 전이는 약 192MiB다. 버퍼 전체와 학습 중 활성값·기울기 메모리는 더 필요하다.
- 환경 수를 2→1로 줄이면서 총 수집량을 유지하려면 n_steps를 1024→2048로 조정한다.

## 5. 결과에 따른 조정 순서

| 증상 | 먼저 확인할 원인 | 다음 후보 |
|---|---|---|
| 오류/NaN/보상 불일치 | 환경 전이·스케일·종료·입력 | 환경 수정. 모델 크기 변경 금지 |
| 직진으로 오래 버팀 | 시간 항이 실제로 지배하는지 | 시간 가중치/보상 스케일 조정 |
| 양끝 방향 명령 반복 | 실제 행동 포화·std·좌우 교대 경로 | 초기 std/entropy 또는 명령 범위 비교. KL이 큰 경우만 학습률/epoch 조정 |
| KL 급증·성능 붕괴 | 업데이트 크기 | learning_rate 5e-5 또는 n_epochs 3. 한 번에 하나만 변경 |
| 학습 환경에서도 개선 없음 | 지도 정보·보상·행동·충분한 학습량 | 원인을 배제한 뒤 큰 모델 C 비교 |
| 학습 성과만 높음 | 시나리오 수·편향·분할 | 학습 다양성 확대, 작은 모델 A 비교 |
| 표적 이동 변화에 잘못 대응 | 현재 입력에 이동 정보가 있는지 | 보류 중인 이동 정보/기억 설계 재검토 |
| 지도에서 관측 띠가 사라짐 | 입력 해상도·집계·초기 downsampling | 첫 CNN stride 1 등 국소 비교. 깊이 증가부터 하지 않음 |
| 모델 연산/메모리가 병목 | 구간별 시간·장치·배치 측정 | batch 32 또는 작은 모델 A |
| 환경 실행이 병목 | 센서 적분·지형·시나리오 생성 | 환경 최적화/병렬화. CNN 축소 효과는 제한적 |

대안 A: CNN 채널 8→16→16, 지도 출력 64, 벡터 16, 결합 128,
actor/critic 각각 64→64. 약 26만 파라미터.

대안 C: CNN 채널 32→64→64, 지도 출력 256, 벡터 32, 결합 256,
actor/critic 각각 128→128. 약 362만 파라미터.

세 모델 모두 Conv 3×3/stride 2/padding 1, Flatten 후 지도별 선형층을 기본으로 한다.

## 6. 실험 운영

1. 환경 검증 후 짧은 파일럿으로 처리속도·메모리·보상 항별 크기·행동 포화를 확인한다.
2. 기준안 B를 고정된 커리큘럼 단계/분포에서 학습해 모델 저장·복원·경로를 확인한다.
3. 증상에 따라 한 종류의 변경만 적용한다. 보상·행동 범위·지도·네트워크를 동시에 바꾸지 않는다.
4. 의미 있는 후보만 같은 평가 시나리오와 복수 학습 seed에서 재비교한다. 총 환경 전이 수와 wall-clock을 함께 기록한다.
5. 커리큘럼/가중치를 바꿀 때는 새 실험 버전으로 기록한다. 정량 성능 합격선은 기존 결정대로 추후 정한다.

추론만으로 정한 숫자를 최적값으로 간주하지 않는다. 실제 Mac과 UAV 환경에서의 학습·속도 검증은 아직 수행하지 않았다.
